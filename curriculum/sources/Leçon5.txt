## PARTIE 1 — Le Cycle du Renseignement

Tout professionnel du renseignement travaille selon un cycle. Sans ça tu es un curieux, pas un analyste.

```
1. PLANIFICATION
   Définir l'objectif précis
   Quelles questions dois-je répondre ?
   Quelles sources sont pertinentes ?

2. COLLECTE
   Rassembler les données brutes
   Sources ouvertes uniquement
   Documenter chaque source

3. TRAITEMENT
   Nettoyer et organiser les données
   Éliminer les faux positifs
   Structurer l'information

4. ANALYSE
   Corréler les données entre elles
   Identifier les patterns
   Formuler des hypothèses

5. DIFFUSION
   Produire un rapport clair
   Destiné à un public précis
   Avec sources vérifiables

6. FEEDBACK
   Évaluer la qualité du renseignement
   Identifier les lacunes
   Affiner pour la prochaine mission
```

**Avant chaque mission OSINT tu dois te poser 3 questions :**
```
QUI   → Quelle est ma cible exacte ?
QUOI  → Quelle information précise je cherche ?
POUR  → Quel est l'objectif légal et éthique ?
```

Sans réponses claires à ces 3 questions — tu ne commences pas.

### Niveau 2 — Techniques avancées

**Google Dorks — chercher ce que Google cache**

Un Google Dork c'est une requête avancée qui exploite les opérateurs de recherche Google pour trouver des informations précises que les recherches normales ne révèlent pas.

```
Opérateurs fondamentaux :

site:domaine.com          → Chercher sur un site précis
filetype:pdf              → Chercher un type de fichier
inurl:mot                 → Mot dans l'URL
intitle:mot               → Mot dans le titre de la page
intext:mot                → Mot dans le contenu
"phrase exacte"           → Recherche exacte
-mot                      → Exclure un mot
OR                        → L'un ou l'autre
```

**Exemples concrets utilisés en investigation :**

```
# Trouver des documents PDF d'une organisation
site:dgrh.cg filetype:pdf

# Chercher une adresse email dans des documents publics
"@dgrh.cg" filetype:pdf OR filetype:doc

# Trouver des fichiers de configuration exposés
filetype:env OR filetype:config "password"

# Chercher un numéro de téléphone dans des pages web
"+242" site:facebook.com

# Trouver des pages d'erreur qui révèlent la technologie
site:cible.com "SQL syntax" OR "PHP error"

# Documents contenant des infos sur une personne
"Jean Claude Mbemba" site:linkedin.com OR site:facebook.com
```

## PARTIE 4 — Investigation sur une Infrastructure

### Analyser un domaine complètement

```
Étape 1 — WHOIS
→ Qui a enregistré le domaine ?
→ Quand ? Expire quand ?
→ Registrar utilisé
→ Serveurs de noms

Étape 2 — DNS
→ Enregistrement A → IP du serveur
→ Enregistrement MX → Service email
→ Enregistrement TXT → SPF, DKIM, vérifications
→ Sous-domaines → surface d'attaque élargie

Étape 3 — IP et hébergement
→ Géolocalisation de l'IP
→ Organisation/ASN
→ Autres domaines sur la même IP (reverse IP)
→ Historique d'hébergement

Étape 4 — Technologies
→ Wappalyzer → stack technique
→ Headers HTTP → serveur, framework
→ Certificat SSL → informations sur l'organisation
→ Shodan → services exposés

Étape 5 — Archives
→ Wayback Machine → anciennes versions du site
→ Google Cache → version récente en cache
→ Archive.today → snapshot manuel
```

### Énumération de sous-domaines

Les sous-domaines révèlent souvent des services internes exposés par erreur.

```
mail.entreprise.com      → Serveur email
admin.entreprise.com     → Interface d'administration
dev.entreprise.com       → Environnement de développement
api.entreprise.com       → API souvent moins sécurisée
staging.entreprise.com   → Tests, parfois avec vraies données
vpn.entreprise.com       → Point d'entrée réseau
ftp.entreprise.com       → Transfert de fichiers
```

**Comment les trouver :**

```python
import dns.resolver
import requests

def enumerer_sous_domaines(domaine, wordlist=None):
    """
    Énumère les sous-domaines d'un domaine
    par force brute sur une liste de mots courants
    """
    if wordlist is None:
        # Liste minimale des sous-domaines les plus courants
        wordlist = [
            "www", "mail", "ftp", "admin", "api", "dev",
            "staging", "test", "vpn", "remote", "portal",
            "webmail", "smtp", "pop", "imap", "ns1", "ns2",
            "blog", "shop", "secure", "login", "cpanel",
            "dashboard", "intranet", "extranet", "cdn"
        ]

    print(f"\n[*] Énumération sous-domaines : {domaine}")
    trouves = []

    for mot in wordlist:
        sous_domaine = f"{mot}.{domaine}"
        try:
            # Tenter la résolution DNS
            # Si ça réussit, le sous-domaine existe
            reponses = dns.resolver.resolve(sous_domaine, "A")
            for r in reponses:
                print(f"  [TROUVÉ] {sous_domaine} → {r}")
                trouves.append({
                    "sous_domaine": sous_domaine,
                    "ip": str(r)
                })
        except (dns.resolver.NXDOMAIN,
                dns.resolver.NoAnswer,
                dns.resolver.Timeout):
            # Le sous-domaine n'existe pas — normal
            pass
        except Exception as e:
            pass

    print(f"\n  {len(trouves)} sous-domaine(s) trouvé(s)")
    return trouves
```

## PARTIE 5 — Géolocalisation d'Images (GEOINT)

C'est une des techniques les plus puissantes et les plus sous-estimées.

### Méthode d'analyse d'une image

```

Les appareils photo embarquent des données invisibles :
- GPS (latitude/longitude exactes)
- Date et heure exactes
- Modèle d'appareil/téléphone
- Logiciel de retouche utilisé

→ Outils : ExifTool, Jeffrey's Exif Viewer

ÉTAPE 2 — Éléments visuels
Si pas de GPS, analyser l'image :
- Panneaux de signalisation (sens de circulation)
- Langue des enseignes
- Architecture typique
- Végétation
- Véhicules (modèles, plaques)
- Uniformes, tenues vestimentaires

ÉTAPE 3 — Recherche inversée
- Google Images

- Yandex Images (très puissant pour les visages)
- Bing Visual Search

ÉTAPE 4 — Verification avec Google Maps/Street View
Une fois la zone identifiée, vérifier
et trouver l'angle exact de la prise de vue
```

### Extraction EXIF en Python

```python
from PIL import Image
from PIL.ExifTags import TAGS, GPSTAGS
# pip install Pillow

def extraire_exif(chemin_image):
    """
    Extrait toutes les métadonnées EXIF d'une image
    Peut révéler la localisation GPS si présente
    """
    try:
        image = Image.open(chemin_image)

        # _getexif() retourne les données brutes
        exif_brut = image._getexif()

        if not exif_brut:
            print("Aucune donnée EXIF trouvée")
            print("Possibles raisons : image retouchée, réseau social")
            print("→ Les réseaux sociaux suppriment l'EXIF automatiquement")
            return {}

        exif = {}
        for tag_id, valeur in exif_brut.items():
            # Convertir l'ID numérique en nom lisible
            tag = TAGS.get(tag_id, tag_id)
            exif[tag] = valeur

        # Afficher les infos importantes
        infos_importantes = [
            "Make", "Model", "DateTime",
            "GPSInfo", "Software", "Artist"
        ]

        print("\n=== MÉTADONNÉES EXIF ===")
        for info in infos_importantes:
            if info in exif:
                print(f"  {info}: {exif[info]}")

        # Extraire le GPS si présent
        if "GPSInfo" in exif:
            gps = extraire_gps(exif["GPSInfo"])
            if gps:
                lat, lon = gps
                print(f"\n  🎯 LOCALISATION GPS TROUVÉE :")
                print(f"  Latitude  : {lat}")
                print(f"  Longitude : {lon}")
                print(f"  Google Maps : https://maps.google.com/?q={lat},{lon}")

        return exif

    except Exception as e:
        print(f"Erreur : {e}")
        return {}

def extraire_gps(gps_info):
    """
    Convertit les données GPS EXIF brutes
    en latitude/longitude décimales
    """
    def convertir_coord(coord, ref):
        # GPS EXIF stocke en degrés/minutes/secondes
        # On convertit en décimal
        degres = coord[0]
        minutes = coord[1]
        secondes = coord[2]

        decimal = float(degres) + float(minutes)/60 + float(secondes)/3600

        # Sud et Ouest sont négatifs
        if ref in ["S", "W"]:
            decimal = -decimal

        return decimal

    try:
        gps_tags = {}
        for tag_id, valeur in gps_info.items():
            tag = GPSTAGS.get(tag_id, tag_id)
            gps_tags[tag] = valeur

        if "GPSLatitude" in gps_tags and "GPSLongitude" in gps_tags:
            lat = convertir_coord(
                gps_tags["GPSLatitude"],
                gps_tags["GPSLatitudeRef"]
            )
            lon = convertir_coord(
                gps_tags["GPSLongitude"],
                gps_tags["GPSLongitudeRef"]
            )
            return lat, lon
    except:
        pass

    return None
```

## PARTIE 7 — Les Données de Fuites (Breach Data)

### Comprendre les fuites de données

Quand une entreprise est piratée et que sa base de données est volée, ces données se retrouvent souvent publiées sur le dark web puis sur des sites publics. Ces données contiennent fréquemment emails, mots de passe hashés, numéros de téléphone, adresses.

**Usage légal et éthique :** vérifier si TES propres données ont été compromises, ou dans le cadre d'une investigation autorisée.

### Sources légales de vérification

```
haveibeenpwned.com
→ Vérifie si un email est dans des fuites connues
→ Gratuit, légal, créé par Troy Hunt (expert sécurité reconnu)
→ Base : 13+ milliards de comptes compromis

dehashed.com
→ Recherche par email, IP, username, nom, téléphone
→ Partiellement payant

intelx.io
→ Intelligence sur des emails, domaines, IPs
→ Utilisé par les professionnels

Leak-Lookup
→ Base de données de fuites
```

### Ce qu'une fuite révèle sur une cible

```
Email compromis dans breach → 
→ Mot de passe hashé (parfois crackable)
→ Autres comptes liés (même mot de passe réutilisé ?)
→ Ancienne adresse IP de connexion
→ Date de la compromission
→ Services utilisés par la cible
```

### Capturer et préserver les preuves

```python
import requests
import hashlib
import datetime
import os

def archiver_preuve(url, dossier_preuves="preuves"):
    """
    Archive une page web comme preuve
    Horodatage + hash pour intégrité légale
    """
    # Créer le dossier si nécessaire
    os.makedirs(dossier_preuves, exist_ok=True)

    timestamp = datetime.datetime.now()
    horodatage = timestamp.strftime("%Y%m%d_%H%M%S")

    try:
        # Télécharger le contenu
        headers = {
            "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"
        }
        r = requests.get(url, headers=headers, timeout=10)
        contenu = r.text.encode("utf-8")

        # Calculer le hash SHA256 pour prouver l'intégrité
        hash_preuve = hashlib.sha256(contenu).hexdigest()

        # Sauvegarder le contenu
        nom_fichier = f"{dossier_preuves}/preuve_{horodatage}.html"
        with open(nom_fichier, "wb") as f:
            f.write(contenu)

        # Créer la fiche de preuve
        fiche = {
            "url_source": url,
            "date_capture": timestamp.isoformat(),
            "fichier": nom_fichier,
            "sha256": hash_preuve,
            "status_http": r.status_code,
            "taille_bytes": len(contenu)
        }

        # Sauvegarder la fiche
        fiche_nom = f"{dossier_preuves}/fiche_{horodatage}.json"
        import json
        with open(fiche_nom, "w") as f:
            json.dump(fiche, f, indent=4)

        print(f"[+] Preuve archivée : {nom_fichier}")
        print(f"    SHA256 : {hash_preuve}")
        print(f"    Date   : {timestamp.strftime('%d/%m/%Y %H:%M:%S')}")

        return fiche

    except Exception as e:
        print(f"[-] Erreur archivage : {e}")
        return None
```

## PARTIE 9 — OPSEC — Protéger ta propre Identité

Un investigateur OSINT qui ne protège pas son identité devient lui-même une cible.

```
RÈGLES FONDAMENTALES :

1. Ne jamais investiguer depuis ta vraie IP
   → VPN + navigateur dédié
   → Idéalement : machine virtuelle séparée

2. Créer des identités de travail (sock puppets)
   → Compte email jetable pour les recherches
   → Ne jamais utiliser tes vrais comptes

3. Navigateur dédié OSINT
   → Firefox avec extensions :
     - uBlock Origin
     - Privacy Badger
     - User-Agent Switcher

4. Ne jamais visiter la cible directement
   → Utiliser les caches Google
   → Wayback Machine
   → Archive.today

5. Documenter sans contacter
   → Observer sans interagir
   → L'interaction alerte la cible

6. Règle des 3 sources
   → Une information confirmée par une seule source
     n'est pas une information fiable
   → Minimum 3 sources indépendantes pour conclure
```

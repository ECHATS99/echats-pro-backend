## PARTIE 2 — Lire un CVE en Anglais

Un CVE (Common Vulnerabilities and Exposures) c'est la fiche technique officielle d'une vulnérabilité. Tu dois en lire plusieurs par semaine pour rester à jour.

### Structure d'un CVE

```
CVE-2021-44228 (Log4Shell — exemple réel célèbre)

DESCRIPTION:
Apache Log4j2 2.0-beta9 through 2.15.0 (excluding security releases)
JNDI features used in configuration, log messages, and parameters
do not protect against attacker controlled LDAP and other JNDI
related endpoints. An attacker who can control log messages or log
message parameters can execute arbitrary code loaded from LDAP
servers when message lookup substitution is enabled.

CVSS Score: 10.0 (Critical)
CWE: CWE-917
```

### Traduction et analyse mot par mot

```
"excluding security releases"
→ "à l'exclusion des versions de sécurité"
→ Les versions correctives ne sont pas affectées

"do not protect against attacker controlled"
→ "ne protègent pas contre [les endpoints] contrôlés par l'attaquant"
→ L'attaquant peut manipuler ces endpoints

"who can control log messages or log message parameters"
→ "qui peut contrôler les messages de log ou leurs paramètres"
→ Condition d'exploitation : contrôle des logs

"can execute arbitrary code"
→ "peut exécuter du code arbitraire"
→ RCE (Remote Code Execution) = critique

"when message lookup substitution is enabled"
→ "quand la substitution de recherche de message est activée"
→ Condition spécifique requise
```

### Vocabulaire CVE récurrent

```
arbitrary code execution  → exécution de code arbitraire
remote code execution     → exécution de code à distance (RCE)
denial of service         → déni de service (DoS)
information disclosure    → divulgation d'informations
authentication bypass     → contournement d'authentification
buffer overflow           → dépassement de tampon
use after free            → utilisation après libération
out of bounds             → hors limites
heap/stack overflow       → débordement de tas/pile
improper validation       → validation incorrecte
insufficient sanitization → assainissement insuffisant
```

## PARTIE 3 — Lire un Rapport de Threat Intelligence

Les rapports de menaces publiés par Mandiant, CrowdStrike, ESET sont tous en anglais. Voici comment les décortiquer.

### Extrait typique à analyser

```
"THREAT ACTOR PROFILE — APT28 (Fancy Bear)

APT28 is a sophisticated threat actor attributed to Russian military 
intelligence (GRU). The group has been active since at least 2004 
and primarily targets government, military, and security organizations.

Their TTPs (Tactics, Techniques, and Procedures) include spearphishing 
via weaponized Office documents, exploitation of known vulnerabilities 
in perimeter devices, and living-off-the-land techniques to evade 
endpoint detection and response (EDR) solutions."
```

### Traduction et compréhension

```
"sophisticated threat actor"
→ "acteur de menace sophistiqué"
→ Groupe avancé, pas des amateurs

"attributed to Russian military intelligence (GRU)"
→ "attribué au renseignement militaire russe (GRU)"
→ Attribution étatique

"primarily targets"
→ "cible principalement"
→ Secteurs visés préférentiellement

"weaponized Office documents"
→ "documents Office weaponisés / piégés"
→ Fichiers Word/Excel avec macros malveillantes

"living-off-the-land techniques"
→ "techniques de subsistance sur le terrain" (LOLBins)
→ Utilisation des outils légitimes du système

"to evade endpoint detection and response"
→ "pour contourner la détection et réponse sur les endpoints"
→ EDR = antivirus avancé, comportemental
```

## PARTIE 4 — Écrire en Anglais Technique

### Rédiger une vulnérabilité en anglais

Structure standard en anglais que tu dois maîtriser :

```
VULNERABILITY REPORT

Title: SQL Injection on Login Form
Severity: Critical
CVSS Score: 9.8

Description:
The login form at /api/auth/login is vulnerable to SQL injection 
via the 'email' parameter. The user-supplied input is not properly 
sanitized before being passed to the database query.

Proof of Concept:
Parameter: email
Payload: admin@target.com' OR '1'='1' --
Result: Authentication bypass — access granted without valid password

Impact:
An unauthenticated attacker can bypass authentication and gain 
unauthorized access to any user account, including administrator 
accounts. This may lead to full database compromise.

Remediation:
1. Implement parameterized queries (prepared statements)
2. Apply input validation on all user-supplied data
3. Deploy a Web Application Firewall (WAF)
4. Enable detailed logging for authentication attempts

References:
OWASP: https://owasp.org/www-community/attacks/SQL_Injection
CWE-89: Improper Neutralization of Special Elements in SQL Query
```

### Vocabulaire d'écriture technique

```
VERBES COURANTS :
to exploit      → exploiter
to patch        → corriger / patcher
to mitigate     → atténuer
to bypass       → contourner
to enumerate    → énumérer
to leverage     → tirer parti de / utiliser
to trigger      → déclencher
to inject       → injecter
to intercept    → intercepter
to authenticate → s'authentifier
to escalate     → escalader / remonter
to harden       → durcir

EXPRESSIONS CLÉS :
"An attacker who can..."    → "Un attaquant qui peut..."
"This may lead to..."       → "Cela peut conduire à..."
"Successfully exploited..." → "Exploitée avec succès..."
"We recommend..."           → "Nous recommandons..."
"As a result..."            → "Par conséquent..."
"In order to..."            → "Afin de..."
"It is recommended that..." → "Il est recommandé que..."
```

## PARTIE 6 — Lire la Documentation Technique

### Décrypter une page de man (manuel Linux)

```bash
NAME
    nmap - Network exploration tool and security / port scanner

SYNOPSIS
    nmap [Scan Type...] [Options] {target specification}

DESCRIPTION
    Nmap ("Network Mapper") is an open source tool for network 
    exploration and security auditing. It was designed to rapidly 
    scan large networks, although it works fine against single hosts.
```

**Traduction et analyse :**

```
"Network exploration tool" → outil d'exploration réseau
"security / port scanner"  → scanner de sécurité / ports
"SYNOPSIS"                 → résumé de la syntaxe
"[Scan Type...]"           → type de scan entre crochets = optionnel
"{target specification}"   → cible entre accolades = obligatoire
"designed to rapidly scan" → conçu pour scanner rapidement
"although it works fine"   → bien qu'il fonctionne bien aussi
"against single hosts"     → contre des hôtes uniques
```

### Lire les messages d'erreur en anglais

```
"Connection refused"
→ La connexion a été refusée
→ Le port est fermé ou le service ne tourne pas

"Connection timed out"
→ La connexion a expiré
→ Firewall bloque ou l'hôte ne répond pas

"Permission denied"
→ Permission refusée
→ Droits insuffisants

"No route to host"
→ Aucune route vers l'hôte
→ Problème réseau ou hôte inexistant

"Name or service not known"
→ Nom ou service inconnu
→ Résolution DNS échouée

"SSL certificate verify failed"
→ Vérification du certificat SSL échouée
→ Certificat invalide, expiré ou auto-signé

"Too many authentication failures"
→ Trop d'échecs d'authentification
→ Blocage après trop de tentatives
```

## PARTIE 7 — Anglais pour les Certifications

Les certifications que tu viseras après cette formation sont toutes en anglais. Voici les formulations récurrentes dans les examens.

### Questions types et comment les lire

```
Q: "Which of the following BEST describes 
    the principle of least privilege?"

Décryptage :
"Which of the following" → parmi les choix suivants
"BEST describes"         → décrit le MIEUX (attention au superlatif)
"principle of least privilege" → principe du moindre privilège

→ Chercher toujours le "BEST" — pas juste "correct" mais "le plus juste"

---

Q: "An attacker has gained access to a system 
    and wants to maintain persistence. 
    Which technique would MOST LIKELY be used?"

Décryptage :
"has gained access"     → a obtenu un accès (passé composé = déjà fait)
"wants to maintain"     → veut maintenir (objectif futur)
"persistence"           → persistance (après reboot)
"MOST LIKELY be used"   → serait le PLUS PROBABLEMENT utilisé
```

### Mots pièges dans les certifications

```
"EXCEPT"    → SAUF — question inversée, cherche l'exception
"NOT"       → PAS — lit bien avant de répondre
"BEST"      → le MEILLEUR — pas juste correct, le plus approprié
"FIRST"     → EN PREMIER — ordre des actions qui compte
"MOST"      → le PLUS — degré maximal
"LEAST"     → le MOINS — degré minimal
"ALWAYS"    → TOUJOURS — absolu, rarement la bonne réponse
"NEVER"     → JAMAIS — absolu, rarement la bonne réponse
```
